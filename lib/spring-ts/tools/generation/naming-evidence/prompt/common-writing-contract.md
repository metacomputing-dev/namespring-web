# 작명 근거 텍스트 공통 집필 계약

## 서비스 관점

이름봄은 사주 풀이 서비스가 아니라 이름을 제안하는 작명 서비스다. 사주 정보는 이름이 왜 적절한지를 판단하는 내부 근거로만 사용한다. 독자가 읽는 기본 설명은 사주를 길게 풀이하지 않고, 현재 필요한 방향과 이름이 그 방향에 얼마나 어울리는지를 설명해야 한다.

## 독자와 어조

- 한국의 일반 사용자가 별도 배경지식 없이 바로 이해할 수 있는 자연스러운 현대 한국어로 쓴다.
- 존댓말 `~해요`, `~이에요`, `~예요`를 일관되게 사용한다.
- 상담자가 차분하게 근거를 설명하는 어조를 사용하되 운명을 단정하거나 불안을 조장하지 않는다.
- 번역투, 시적인 비유, 추상적인 수사, 사전식 정의를 피한다.
- `고른 결`, `낮은 흐름`, `기운의 그릇`, `삶의 리듬`처럼 의미가 모호한 조어를 만들지 않는다.
- 모든 조합을 좋게 포장하지 않는다. 부족한 경우에는 무엇이 제한적인지 말하되 이름 전체를 부정하지 않는다.

## plain과 detail의 역할

`plain`은 사용자가 기본 화면에서 읽는 설명이다.

- 전문용어인 `일간`, `신강`, `신약`, `중화`, `용신`, `격국`, `인성`, `식상`, `재성`, `관성`, `비겁`을 사용하지 않는다.
- 오행 한자나 코드값을 나열하지 않는다.
- 먼저 사주에서 필요한 방향을 설명하고, 그 다음 이름에 실제로 포함된 성분이 그 방향을 어떻게 돕거나 제한하는지 말한다.
- 하나의 문장은 하나의 핵심 주장만 담당한다.

`detail`은 상세 근거 화면에서 읽는 설명이다.

- 해당 작업에서 제공한 일간, 신강약, 용신, 격국 또는 점수 축의 전문용어를 정확하게 사용한다.
- 전문용어를 나열하는 데 그치지 말고, 각 값이 이름 판단에 어떤 의미를 갖는지 인과관계로 설명한다.
- 입력에 없는 생년월일, 성별, 사건, 가족관계, 직업 또는 이름의 한자를 지어내지 않는다.

## 문장 조립을 위한 규칙

각 fragment는 `사주 4축 설명 → 영향도가 큰 이름 근거 2~3개 → 결론` 순서로 이어져 하나의 글이 된다. 개별 fragment만 자연스러운 것보다 전체를 연속해서 읽을 때 주어와 평가가 반복되지 않는 것이 더 중요하다.

- fragment 첫 문장을 `하지만`, `또한`, `따라서`, `반면`, `그리고`, `다만` 같은 접속어로 시작하지 않는다.
- 앞 문장의 지시어에 의존하는 `이러한`, `이처럼`, `그 결과`, `이 경우`로 시작하지 않는다.
- 다른 fragment가 없어도 문법적으로 완결된 문장이어야 한다.
- 같은 주장을 앞뒤 fragment에서 반복하지 않는다.
- `사주에 필요한 방향`, `이름의 전체 구성`, `보완`, `조화` 같은 핵심 명사는 가까운 문장에서 반복하지 않도록 자연스럽게 바꿔 쓴다.
- 사주 4축 fragment가 필요한 방향을 제시하고 원천 근거 fragment가 그 판단을 이어받는다. 원천 근거마다 사용자 이름을 다시 주어로 세우지 않는다.
- 사용자 이름은 원천 근거 fragment에서 반복하지 않고 최종 결론에서 자연스럽게 한 번 언급하는 것을 기본으로 한다.
- 원천 근거의 첫 문장은 sourceId마다 관점을 달리한다. 부족·과다 상태, 필요한 조절 방향, 실제로 확인된 성분, 제한 요인 가운데 해당 근거의 핵심 사실부터 시작한다.
- 이름 자리표시는 허용된 `{{name}}`, `{{name:topic}}`만 사용한다. 조사까지 필요한 주어에는 `{{name:topic}}`을 사용한다.
- `{{name:topic}}`은 치환할 때 이름 뒤에 `은/는`이 붙는다. 뒤에 다른 조사를 다시 붙이지 말고, `에`, `에서`, `으로`, `와/과` 등이 필요하면 `{{name}}`을 사용한다.

## 근거와 결론

- 근거 없이 `좋아요`, `잘 맞아요`, `안정적이에요`라고 평가하지 않는다.
- 점수나 등급을 자연어 평가로 바꿔 쓰는 것을 근거로 간주하지 않는다.
- `어떤 성향 때문에 무엇이 필요하고, 이름의 어떤 오행 성분과 계산 근거가 그 필요에 어떻게 연결되는지`가 드러나야 한다.
- 실제 계산에 사용된 원천 근거만 쓰고, 가중치가 큰 근거를 먼저 설명한다.
- 이름이 사주의 결핍을 완전히 해결하거나 사람의 성향을 바꾼다고 표현하지 않는다.
- 점수가 낮은 경우에도 위험, 실패, 불행을 예고하지 않는다. `보완 근거가 약하다`, `다른 후보와 비교할 필요가 있다`처럼 추천 판단의 범위에서 쓴다.

## 길이

- 사주 4축 fragment: plain 90~170자, detail 110~210자
- 원천 근거 fragment: plain 55~140자, detail 50~150자
- 결론 fragment: plain 45~90자, detail 55~120자
- 분량을 채우기 위한 반복 문장을 쓰지 않는다. 권장 범위보다 짧더라도 의미가 완결되면 군더더기를 추가하지 않는다.

## 최종 자체 점검

출력 전에 각 항목을 다음 기준으로 다시 읽는다.

1. plain만 읽어도 사주에 필요한 방향을 이해할 수 있는가.
2. detail의 전문용어와 입력값이 정확히 일치하는가.
3. 평가와 그 근거 사이에 인과관계가 있는가.
4. 실제로 알 수 없는 개인의 경험을 사실처럼 말하지 않았는가.
5. 다른 항목의 문장과 바꾸어 넣어도 똑같이 들리는 범용 문장이 아닌가.
6. 한국어 화자가 일상적인 상담 글에서 사용하지 않을 표현이 남아 있지 않은가.
7. 전체 글로 이어 읽었을 때 각 근거가 사용자 이름이나 `이름에는`을 반복해서 다시 시작하지 않는가.
8. 오행 성분을 말한 뒤 그 성분이 어떤 기능을 뜻하고 왜 현재 작명 방향에 도움이 되거나 제한적인지 설명했는가.
