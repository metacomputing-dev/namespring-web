# 사주 4축 fragment 생성 과제

아래 `task`에는 일간, 신강약, 용신이 공통이고 격국 계열만 다른 항목들이 들어 있다. 모든 항목을 함께 비교해서 작성하라. 공통 축의 설명은 일관되어야 하지만, 격국에 따라 필요한 이름의 역할과 판단 근거가 분명히 달라야 한다.

## 작성 책임

- `plain`: 현재 성향이 어떤 방식으로 힘을 쓰기 쉬운지 한 문장으로 설명하고, 이름에서 어떤 방향을 보완해야 하는지 인과관계가 이어지는 2~3문장으로 쓴다.
- `detail`: 일간, 신강약, 용신, 격국 계열을 모두 정확히 언급하고, 네 값의 결합이 왜 해당 작명 방향으로 이어지는지 2~3문장으로 설명한다.
- 특정 이름의 실제 점수나 적합성을 평가하지 않는다. 이 fragment는 이름을 평가하기 전의 사주 상태와 작명 기준만 담당한다.
- 여섯 격국 결과의 첫 문장 구조와 종결 표현을 반복하지 않는다.
- 여섯 plain에서 `이름은 A보다 B가 필요해요` 또는 `A를 더하기보다 B를 보완해야 해요` 같은 대비 문형은 각각 두 번까지만 사용한다. 나머지는 원인 설명, 판단 기준, 필요한 역할의 순서를 바꾸어 쓴다.
- 여섯 detail을 모두 `○ 일간이 ○하고 용신이 ○이면` 같은 동일한 축 나열 문형으로 시작하지 않는다. 전문용어는 정확히 유지하면서 네 축의 관계를 먼저 드러내는 문장도 섞는다.
- `필요해요`, `보완해야 해요`, `중요해요` 중 하나의 종결을 여섯 항목에서 세 번 이상 반복하지 않는다.
- 축 의미를 `A는 무엇이고 B는 무엇이다`처럼 나열하지 않는다.

## 품질 기준 예시

좋은 방향:

> 새로운 가능성을 찾는 감각은 좋지만, 스스로 밀고 나가는 힘은 쉽게 소진될 수 있어요. 생각을 충분히 익힌 뒤 움직이는 편이므로, 이름에는 조급함을 더하기보다 꾸준히 힘을 보태는 성분이 필요해요.

피해야 할 방향:

> 목의 기운은 성장의 흐름을 가지고 있어요. 신약하므로 수의 기운이 필요해요. 인성의 결을 살리는 이름이 좋아요.

첫 예시는 원인과 필요한 방향이 연결된다. 두 번째 예시는 축 설명을 이어 붙였을 뿐 판단 과정이 없다. 예시의 문장을 출력에 복사하지 말라.

## 작업 데이터

{{TASK_JSON}}

## 출력

설명이나 Markdown 없이 지정된 JSON 스키마만 반환하라. `taskId`는 입력값을 그대로 쓰고, `items`에는 요청된 key를 각각 정확히 한 번 포함하라.
