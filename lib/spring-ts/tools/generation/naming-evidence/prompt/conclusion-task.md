# 사주 적합성 결론 fragment 생성 과제

앞에서 사주 4축의 현재 상태와 이름의 원천 근거를 설명한 뒤 마지막에 붙는 결론을 작성하라. 새로운 근거를 추가하지 말고, 실제 계산 가중치가 큰 근거와 확인된 제한을 종합해 추천 판단만 정리한다.

## 결론 유형

- allPositive: 핵심 원천 근거와 보조 근거가 모두 긍정적이다. `우선 추천해도 좋은 이름`처럼 분명하게 추천할 수 있다.
- mostlyPositive: 가중치가 큰 원천 근거가 긍정적이고 일부 보조 제한만 있다. `추천 후보로 살펴볼 만하다`고 쓸 수 있지만 완벽하다고 말하지 않는다.
- mixedButUsable: 긍정과 제한이 섞여 있다. `좋은 이름`, `추천할 만한 이름`, `충분한 후보`라고 결론 내리지 말고 다른 후보와 비교하도록 안내한다.
- needsCaution: 종합 적합성이 낮거나 주의 근거가 많다. 우선 추천하지 않는다는 뜻을 분명히 밝히고 다른 후보를 먼저 보도록 안내한다.
- insufficientEvidence: 확인 가능한 원천 근거가 없어 결론을 보류해야 한다.

## 작성 책임

- 앞 문장을 요약하되 `종합하면`으로 모든 문장을 시작하지 않는다.
- `{{name:topic}}` 또는 `{{name}}`을 자연스러운 경우 한 번만 사용한다.
- 추천 강도는 유형에 정확히 맞춘다.
- allPositive와 mostlyPositive의 차이, mixedButUsable과 needsCaution의 차이가 분명해야 한다.
- insufficientEvidence에서는 이름이나 사주가 나쁘다고 해석하지 말고 판단 자료가 부족하다고만 설명한다.
- plain은 한 문장을 우선하며, detail도 새로운 분석을 덧붙이지 않는다.
- `사용 가능한 후보`, `추천 판단`, `제한 요인`, `종합 적합성`처럼 시스템 판정문으로 들리는 표현은 사용자용 plain에 쓰지 않는다.
- detail도 plain보다 더 낙관적으로 결론 내리지 않는다.

## 작업 데이터

{{TASK_JSON}}

## 출력

설명이나 Markdown 없이 지정된 JSON 스키마만 반환하라. `taskId`는 입력값을 그대로 쓰고, `items`에는 요청된 key를 각각 정확히 한 번 포함하라.
