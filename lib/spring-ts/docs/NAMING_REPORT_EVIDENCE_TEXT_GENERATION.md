# 작명 보고서 근거 문안 생성 설계

## 목적

이름봄은 사주 풀이가 아니라 작명 서비스다. 사주 분석은 UI에서 직접 설명하지 않고, 추천 이름이 사용자에게 왜 적합한지를 뒷받침하는 내부 근거로 사용한다.

통합 보고서의 2번 영역은 다음 세 항목으로 구성한다.

```text
2. 이 이름이 잘 맞는 핵심 이유
  2.1. 사주에 필요한 방향과 맞는가
  2.2. 이름의 성명학 구조가 안정적인가
  2.3. 부르기 좋은 이름인가
```

기본 UI는 자연어 설명인 `plain`을 보여 주고, 상세 보기에서 전문 근거인 `detail`을 제공한다.

## 2.1 입력 모델

사주의 현재 상태는 네 축으로 분류한다.

```text
일간 오행 5 x 신강약 3 x 용신 오행 5 x 격국 계열 6 = 450
```

이름 적합성은 최종 점수 구간을 문장으로 번역하지 않는다. 점수를 만든 다음 원천 사실을 계산 과정에서 보존하고, 확인된 사실만 보고서 조립에 사용한다.

원천 근거는 다음 일곱 종류다.

| 근거 | 실제 관찰 내용 |
| --- | --- |
| `balance` | 이름을 더한 뒤 부족 오행을 채우거나 과다 오행을 더하는지 |
| `yongshin` | 이름 오행이 용신·희신·기신·구신 중 무엇과 만나는지 |
| `strength` | 이름이 신강약에 필요한 조절 방향을 따르는지 |
| `tenGod` | 이름이 부족한 십신 계열을 보완하거나 과한 계열을 더하는지 |
| `deficiency` | 부족 오행 중 용신·희신을 직접 채워 보너스가 생겼는지 |
| `harmfulElement` | 기신·구신이 이름에 포함되어 감점이 생겼는지 |
| `gyeokgukProtection` | 종격 구조를 보호하거나 해쳐 감점이 생겼는지 |

`sajuFit`, `yongshinFit`, `elementBalance`는 위 사실을 압축한 결과값이다. 2.1 문안 선택에는 이 점수 구간을 사용하지 않는다.

## 단일 가중치 정책

계산 모델과 생성 프롬프트가 공유하는 원천은 다음 파일 하나다.

```text
config/naming-evidence-weights.json
```

이 파일에서 관리하는 값:

- 기본 혼합 비율과 동적 범위
- 용신 판단 방법별 가중치
- 학파 프리셋별 override
- 균형·용신·신강약·십신 세부 계산 상수
- 결핍 보너스와 기신·구신·종격 감점 상한
- 생성 대상 원천 근거와 상태 목록
- 근거별 최대 점수 영향도

기본 혼합 비율은 균형 `0.60`, 용신 `0.23`, 신강약 `0.12`, 십신 `0.05`다. 용신 신뢰도와 균형 대비 우위에 따라 균형은 `0.35~0.60`, 용신은 `0.23~0.48` 범위에서 이동한다.

가중치는 다음 세 의미를 구분한다.

1. `calculationValue`: `calculationKind`에 따라 실제 혼합 비율 또는 가감점 상한
2. `maxScoreImpact`: 근거 간 비교가 가능하도록 최종 점수 단위로 환산한 최대 영향도
3. `decisionImpacts`: 현재 이름의 부분 점수가 중립점 50에서 벗어난 정도에 적용 가중치를 곱한 실제 판단 영향도

최대 점수 영향도는 기본 정책에서 균형 60점, 용신 48점, 신강약 12점, 십신 5점, 결핍 보너스 8점, 유해 오행 감점 14점, 종격 감점 20점이다. 런타임 로더가 계산 상수와 이 값의 일치 여부를 검증한다.

학파별 JSON은 이름과 설명만 보관한다. 학파별 계산값은 모두 `naming-evidence-weights.json#/presetOverrides`에 있으며 `loadPreset()`도 이 표에서 조립한다.

## 엔진 근거 보존

`computeSajuNameScore()`는 `SajuNameSourceEvidence`에 다음 정보를 남긴다.

- 실제 적용 가중치
- 네 부분 점수
- 네 부분 점수의 직접 기여값
- 중립점 대비 실제 판단 영향도
- 이름과 결합한 오행 분포
- 채운 부족 오행과 더해진 과다 오행
- 용신·희신·기신·구신의 실제 오행과 일치 횟수
- 신강약 조절에 맞는 오행과 반대 오행
- 십신 보완·제한 오행
- 실제 보너스와 감점
- 종격 적용 및 훼손 여부

보고서 조립기는 긍정 근거와 제한 근거를 각각 보존한 뒤, 실제 판단 영향도가 큰 근거부터 최대 세 개를 선택한다. 입력에서 확인되지 않은 사실은 문안에 넣지 않는다.

## 조립형 문안 DB

모든 사주 상태와 이름 오행 배열을 곱하면 수만 개 이상의 문안이 필요하고 검수도 어렵다. 따라서 2.1은 독립 fragment를 조립한다.

```text
사주 4축 상태 설명 450개
+ 원천 근거 상태 설명 18개
+ 결론 설명 5개
= 총 473개
```

런타임 조립 순서:

```text
1. 사주 4축의 현재 상태와 작명에 필요한 방향
2. 실제 판단 영향도가 큰 긍정 또는 중립 근거
3. 실제 판단 영향도가 큰 제한 근거
4. 남은 근거 중 영향도가 큰 근거
5. 전체 근거 방향에 맞는 결론
```

각 원천 근거 fragment는 `{{filledElements}}`, `{{matchedElements}}`, `{{harmfulElements}}` 같은 제한된 자리표시자를 사용한다. 런타임은 엔진에서 관찰한 실제 오행만 치환한다.

## 생성기

생성기는 운영 DB와 같은 작업 형태를 사용한다.

```text
75개 사주 축 작업 x 격국 6개 = 450행
7개 원천 근거 작업             = 18행
1개 결론 작업                  = 5행
총 83개 작업                   = 473행
```

프롬프트는 다음 디렉터리의 Markdown을 조립한다.

```text
tools/generation/naming-evidence/prompt/
  common-writing-contract.md
  domain-guide.md
  source-evidence-domain-guide.md
  saju-axis-task.md
  source-evidence-task.md
  conclusion-task.md
```

원천 근거 프롬프트에는 공유 정책의 계산 비율, 최대 점수 영향도, 용신 방법 가중치, 프리셋 override가 함께 들어간다. 숫자를 사용자 문장에 노출하지 않고, 강조 수준과 설명 분량을 정하는 데만 사용한다.

LLM을 호출하지 않고 계획을 확인한다.

```bash
npm run plan:naming-evidence-generation
```

운영과 같은 작업 단위로 파일럿을 생성한다.

```bash
npm run generate:naming-evidence-pilot
```

전체 생성은 명시적으로 실행한다.

```bash
npm run generate:naming-evidence
```

전체 473행 생성과 검수가 끝난 뒤에만 DB를 만든다.

```bash
npm run build:naming-evidence-db
```

## DB 계약

DB 스키마 버전은 2이며 다음 테이블을 사용한다.

```text
saju_axis_explanations
source_evidence_explanations
conclusion_explanations
evidence_connectors
metadata
```

빌더는 전체 범위 결과만 허용하고 `450 + 18 + 5` 행 수와 key 중복을 검사한다. 샘플 결과로 운영 DB를 만들지 않는다.

## 문안 품질 원칙

- `plain`은 사주 전문용어 없이 이름에 실제로 포함된 성분과 그 영향을 설명한다.
- `detail`은 필요한 경우에만 일간, 신강약, 용신, 희신, 기신, 구신, 십신, 격국 용어를 쓴다.
- 점수나 등급을 단순히 `잘 맞는다`, `아쉽다`로 번역하지 않는다.
- 원천 사실과 이름 추천 판단 사이의 인과관계를 쓴다.
- 가중치 숫자는 문장에 노출하지 않는다.
- 높은 가중치는 설명의 우선순위이지 무조건 긍정한다는 뜻이 아니다.
- 제한 근거를 공포, 단정, 탈락 표현으로 쓰지 않는다.
- 실제 입력에 없는 개인 상황이나 사건을 만들어 내지 않는다.
- fragment를 의존적인 접속어로 시작하지 않는다.
- 서로 다른 fragment에서 같은 문장 골격을 반복하지 않는다.

## 검증

```bash
npm run test:naming-evidence-generation
npm run test:naming-evidence-report
npm run check:naming-evidence-generation
npm run check:naming-evidence-db
npx tsc --noEmit
```

검증 범위에는 단일 가중치 파일 사용, 모든 프리셋 override 해석, 최대 점수 영향도 일치, 원천 근거 노출, 83개 작업과 473행 완전성, DB 무결성, 자리표시자 치환이 포함된다.
