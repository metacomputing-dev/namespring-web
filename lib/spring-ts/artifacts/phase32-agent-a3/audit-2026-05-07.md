1. Walked all `data/narrative/<cat>/<period>/expert.fragments.json` files
   (55 files) and built a paragraph histogram by `\n\n`-splitting each
   fragment's concatenated `templateTokens` text values. Pre: 87 5p
   source fragments / 33 6p source.
2. For each 5-paragraph fragment, counted fire frequency across 32
   `sample-outputs-2026-05-05-phase3/*-tiered.json` tiered fixtures
   (where `selectedFragments.expert.fragmentId === <fragment>`).
3. Per task brief: P28-A2 / P30-A4 lifted (4p→5p) fragments are eligible
   *if* meaningfully extendable; flagged but not auto-excluded. Selected
   10 fragments from the **non-previously-lifted** pool to keep selection
   independent and avoid re-touching same cells.
4. Optimized for ~+9 cell delta (task target 11 → ~20), not max fire:

## Flow-cluster防 design

P29-A1 root-cause: `reduceOverusedGyeol` substitutes `결X` particle
forms (`결이`, `결로`, `결의` 등) to `흐름X` until paragraph-budget
exhausted (initial 흐름 count + sub count > 2 → falls to alt forms).
For each new 6th paragraph:

1. **Source 흐름이 = 0** in the new paragraph (8 of 10 frags) or
   matches the existing fragment's flow density (2 frags).
2. **Eligible `결X` particles ≤ 1** in the new paragraph (8 of 10
   frags use `자리`/`호흡`/`자세` instead of `결이`/`결로`/`결의`),
   so the simulated render flow count stays ≤2 per paragraph.
3. **No `결X` immediately after a tag-token boundary** (P29-A1 lesson)
   — the only tag-adjacent text in new 6th paragraphs is
   `romance.life.expert.teen.001`'s `#배우자궁의 자리`, which uses
   `자리` not `결X`.

1705 rendered cells in the 32-fixture matrix.
