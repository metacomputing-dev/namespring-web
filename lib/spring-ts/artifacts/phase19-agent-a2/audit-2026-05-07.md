## Headline

P18-A5 audit (`audit-2026-05-07-phase18.md` §A) catalogued a NEW post-
processor leak class that `ci:post-processor-grammar`'s 4 single-token
patterns did not detect: the `GYEOL_SUBS` table in
`src/report/tiered/template-engine.ts` rewrites `결X` particle suffixes
without a `(?<![가-힣])` lookbehind, so any `[가-힣]결X` compound (esp.
the noun `연결`) gets mangled — `연결을` → `연흐름을`, etc. P18-A5 fixed
the source side in `_coverage/` (24 files, 31 substitutions) and
caught the leak via measure-only tooling. Phase 19 promotes the
detection to the production ratchet.

P19-A2's contribution: 13 new patterns added to
`tools/check_post_processor_grammar.mjs`, organized into two families:

| Family | Pattern count | Purpose |
|--------|---------------|---------|
| Source-side `연결+조사` (을/이/로/의/에/과/도/만) | 8 | Catch any 연결+조사 form that survived to rendered output |
| Sink-side `연흐름`/`연리듬`/`연자리`/`연호흡`/`연걸음` | 5 | Catch the GYEOL_SUBS-mutated forms (broken Korean) |

Both families use `(?<![가-힣])` lookbehind to avoid false positives on
hangul-prefixed compounds where the substring is incidental. All 13
new rule entries reuse the existing `walkPlainText` traversal (post-
processed user-visible surface only), preserving the pre-existing
design choice to scan `plainText`-keyed fields exclusively.

## Lookbehind design

All 13 new patterns use `(?<![가-힣])` (negative lookbehind for any
hangul) before the literal substring:

```
/(?<![가-힣])연결을/g
/(?<![가-힣])연흐름/g
…
```

Rationale:

- **Source-side**: prevents matching when `연결+조사` is a tail of a
  4+-char hangul compound where `연` itself is part of a different
  morpheme (very rare in modern Korean prose, but the lookbehind is
  cheap insurance against false positives in expanded vocabularies).
- **Sink-side**: prevents flagging hypothetical `[가-힣]연흐름`
  compounds that contain the substring incidentally. The
  `reduceOverusedGyeol` post-processor only emits `연흐름` (etc.) when
  the source token was bare-stem `연결`; it never produces a
  hangul-prefixed `[가-힣]연흐름` form. So the lookbehind is purely
  defensive.

The right side of each pattern is a postpositional particle (을/이/로/
의/에/과/도/만) or a fixed alternative-stem prefix (흐름/리듬/자리/호흡/
걸음); both are morphologically self-bounded — no separate `\b` or
right-side lookahead needed. Korean does not use ASCII word boundaries.

The patterns intentionally do NOT cover verb forms (`연결되어`,
`연결하여`, `연결되지만`, etc.). Only postpositional particle attachment
to `결` triggers GYEOL_SUBS, so verb forms are not a leak class.
