## Issues fixed this phase

### A. Compound `연결X` post-processor collision in `_coverage/`

The post-processor in `src/report/tiered/template-engine.ts`
defines `GYEOL_SUBS` as a per-particle table (`결이|결을|결로|
결은|결의|결도|결만|결처럼|결마다|결이에요|결입니다|결이라|
결이고`) and applies each pattern globally without word-boundary
exclusion. When the source token is "연결" (connection / link /
bond), the trailing `결X` particle matches and rewrites the
character — producing `연흐름X` (or `연리듬X`, `연자리X`, etc.
when the density budget triggers an alternative). This is broken
Korean: "연흐름" is not a word.

P18-A5 root-causes the leak by rewording at the source
(`_coverage/` data) rather than the engine (forbidden scope), so
the post-processor never sees a particle directly suffixed to a
`결`-terminal compound. The replacement noun `연결고리`
("connection link") has identical semantics in the affected
contexts (elderly-care relationship continuity, day-master /
yongshin / season action density) and breaks the collision because
the particle attaches to `리`, not `결`.

### C2. Per-text vs per-fragmentId hook dormancy reconciliation

`measure_p18_a5.mjs` reports `dormantHookStrings: 1` (the source
form `쌓아 온 결이 자리를 받쳐 줘요`). This is a counting artifact:
the post-processor mutates `결이 → 흐름이`, so the hook is emitted
as `쌓아 온 흐름이 자리를 받쳐 줘요` (7 cells per
`post-fix-snapshot.json`'s `perHookOccurrence`). The canonical
per-fragmentId view used by `measure_p18_a2.mjs` correctly shows
**0 / 34** dormant.

This hook is a deliberate authoring choice (P18-A2 §3 expansion)
that exercises the GYEOL post-processor substitution as part of
its emit form. A measure tool that counts post-processor-mutated
emits as dormant is double-counting.

**No action**: tracked as an audit-tool counting artifact only.
Future measure scripts should apply post-processor substitution to
authored hooks before comparing against emitted text (see
`measure_p18_a2.mjs`'s `applyPostProcessor` helper for the
reference pattern).
