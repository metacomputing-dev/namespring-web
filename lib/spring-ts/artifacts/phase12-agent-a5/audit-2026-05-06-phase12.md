## Audit methodology

### Tooling produced this phase

1. `extract-prose.mjs` — corpus extractor (carried over from P11-A5,
   now produces 11,585 prose units across 32 tiered fixtures).
2. `audit-phase12.mjs` — runs 6 detectors on every prose unit:
   - **word_repeat**: 3-4 char Korean substring repeated within 0-3
     chars (false-positive-filtered against 있어요/없어요/이번 등).
   - **awkward_phrase**: curated patterns (과 함께 함께 / 그 그 /
     그리고 그리고 / 이 자리, 이 자리 / X을 X을).
   - **audience_leak**: adult vocabulary (결혼, 연봉, 이직 등 27 terms)
     in fixtures where age ≤ 13 (infant/child/preteen).
   - **korean_grammar**: period-then-no-space, doubled punctuation,
     comma-before-terminal patterns.
   - **depth_inversion**: brief headline length > standard.para0 length
     (structural inversion).
   - **bare_glossary_label**: known glossary label of 3+ chars appearing
     as bare prose followed by `의 (결이|결과|자리|흐름|신호|기운)`,
     filtered against length-2 ambiguous labels (용신/식신/etc.).
3. `find-orphans-residual.mjs` — sibling-axis heuristic detector. For
   each fragment:
   - groups all 4,077 fragments by `(category, period, depth)` axis;
   - for each label of length ≥ 3, computes `(asTag, asText)` count
     per axis;
   - flags any fragment where the label appears as bare text AND the
     same label is used as tag in ≥ 80% of axis siblings AND the
     fragment itself uses the label as a tag elsewhere (so it is an
     inconsistent re-mention, not a deliberate "intro tagged then
     rephrase without #" pattern).
4. `apply-flow-cluster-fix.mjs` — idempotent applicator that rewrites
   `자산 운영 결이` → `자산 운영 호흡이` across 19 fragment files. Reduces
   the 3-흐름이 cluster in `wealth/thisWeek/expert/para2` and the parallel
   season-context fragments to 2.

## Issues fixed this phase

### A. Residual orphan-tag-text (2 fragments, 5 token splits)

Sibling-axis detector `find-orphans-residual.mjs` surfaced two fragments
not caught by P11-A5's three precision-targeted detectors. The pattern
matches P11-A5 §A1-A3 — bare label inside text token where parallel
sibling fragments at the same axis use the tag form for the same word.

| File | Fragment | Missing tag(s) | Fixture impact |
|------|----------|----------------|----------------|
| `_coverage/movement-short-season-context.fragments.json` | `movement.thisWeek.expert.currentseason.spring_summer.301` | `daewoonGungsil` (대운궁실) | 19 |
| `family/thisYear/expert.fragments.json` | `family.thisYear.expert.young_caregiver.009` | `bumyong` (부모궁), `jojangung` (조상궁) — same fragment, 2 splits | 5 |

Both were applied as in-place text-token splits + re-injection of `tag`
tokens. No `tags` array changes needed — the corresponding tagIds were
already in the array (as expected — earlier in the same fragment those
labels are tags).

#### Why the P11-A5 detectors missed these

P11-A5's `find-bare-tag-leadin.mjs` required the bare label and an
adjacent tag token to appear in the SAME text token within a tight
window. P11-A5's `find-bare-leadin-broader.mjs` and `find-bare-leadin-v3.mjs`
required the bare label to occur immediately AFTER another tag in the
rendered text. Both fragments here have the bare label in mid-sentence
(after a paragraph break or after a non-glossary connecting word),
which fell outside those window patterns.

`find-orphans-residual.mjs` (this phase) replaces window-based proximity
with sibling-axis cross-tag stats: if ≥ 80% of fragments at the same
`(category, period, depth)` axis use the label as a tag (and never
bare text), any bare-text occurrence in the fragment is presumed a
regression.

#### Doctrine refinement vs. P11-A5

P11-A5's audit (§A "How detected" → "False-positive control") carved
out same-fragment "intentional re-mention" as legitimate Korean style:
once a topic is introduced as a hashtag (`#식신…`), repeating it later
as bare text (`…식신의…`) within continuous prose was treated as clean
style. P12-A5 narrows that carve-out: same-fragment re-mention is
legitimate only inside continuous prose, not when the bare-text
mention is separated from the introducing tag by a paragraph break
(`\n\n`) or by intermediate axis-context that resets reader attention.
Both P12-A5 fixes are paragraph-break separated; the bare-text mention
acts as a "fresh" introduction in a new paragraph, where the parallel
sibling fragments at the same axis consistently use the tag form.

### B. Post-processor-induced 흐름이 cluster polish (1 file × 1 token + 19 files × 30 tokens)

`src/report/tiered/template-engine.ts:686` runs an unconditional
`결이 → 흐름이` rewrite as part of `reduceOverusedGyeol`. Source prose
that authored two `결이` near a closing `흐름이` produces 3 `흐름이` in
one short sentence after rewriting. Two specific sentence templates hit
36 fixture cells:

- **Movement weekly:** `이동의 결이 자기 자산으로 익어 가는 흐름이 보여요`
  → after post-process: `이동의 흐름이 ... 익어 가는 흐름이`. Combined
  with `#대운궁실의 흐름이 새로운 자리로 들어오는` (also rewritten) yields
  3 흐름이.
  - Fix: `이동의 결이 자기 자산으로 익어 가는 흐름이` →
    `이동 호흡이 자기 자산으로 익어 가는 모양이`.
  - Single token edit; 19 fixtures benefit.
- **Wealth (any-period) sentence:** `의 결이 또렷한 사주는 자기 격에 맞는 자산 운영 결이 자연스럽게 자리 잡아요`
  → after post-process: `의 흐름이 또렷한 사주는 ... 자산 운영 흐름이`.
  Combined with `#편재격` / `#정재격` flow fragments produces 3 흐름이.
  - Fix: `자산 운영 결이 자연스럽게` → `자산 운영 호흡이 자연스럽게`.
  - Bulk edit via `apply-flow-cluster-fix.mjs`; 19 files, 30 token
    replacements; 17+ fixtures benefit.

#### Why this is a polish, not a hard contract

Three `흐름이` in one sentence is not a content bug or AI policy
violation — the prose still parses as natural Korean. It is a readability
regression introduced by the post-processor's design choice to undo
"overused 결" globally rather than by sentence. Authoring source prose
to avoid a third `결이` adjacent to a closing `흐름이` sidesteps the
issue entirely.

After fixes:

| Cluster size | Distinct strings | Distinct strings (before P12-A5) |
|--------------|------------------|----------------------------------|
| 3+ 흐름이    | 15 strings       | 17 strings                       |
| in ≥ 5 fxs   | 1 string         | 4 strings                        |
| in ≥ 17 fxs  | 0                | 2 strings (movement, wealth)     |

The largest remaining cluster fires in 5 fixtures (career/life/standard
"인생 전체의 직업 방향" sentence) and is harder to reword without
changing register; left as a deferred polish.

on the brief tier contract. `NarrativeFragment.hookSlot?: string`
(`src/report/tiered/fragment-registry.ts:66`) is declared on the

- **Phase 13 (or P12 src/ owner)**: implement hook-rendering pipeline
  if the schema is intended to be live. Either the contract is

src/ rendering would produce dead data.

### High priority

1. **Phase 13 — Productionize `find-orphans-residual.mjs` as
   `ci:narrative-orphan-tag-residual` gate.** Same input shape as the
   existing `ci:narrative-tag-label-alignment` gate. Sibling-axis
   cross-tag heuristic catches the patterns P11-A5's window-based
   detectors miss. Threshold: 0 violations.

2. **Phase 13 — Audit `template-engine.ts` post-processor cluster
   triggers.** The `결이 → 흐름이` chain at line 686 is a global
   rewrite; consider sentence-aware variants that don't trigger when
   the result would produce 3+ `흐름이` in close proximity. P12-A5 used
   data-side rewording as a workaround; src-side fix is cleaner.

### Medium priority

3. **Phase 13 — Decide `brief.hook` schema fate.** Either:
   a. Implement hook rendering: add `hookSlot` author surface,
      `compose()` pipeline that emits `BriefFortuneText.hook`, and a
      contract test that asserts non-empty hook for ≥ N brief cells.
   b. Drop `BriefFortuneText.hook?` from `src/report/types.ts` and
      `NarrativeFragment.hookSlot?` from the fragment registry.

4. **Phase N — Expert-depth floor variation.** As noted in P11-A5 §B1:
   the median expert distinct ratio of 0.107 reflects single-variant
   wildcard floors. Worth a dedicated thread on whether to author
   multiple variants per floor.

### Low priority / informational

5. **Detector productionization.** `find-orphans-residual.mjs` and
   `audit-phase12.mjs` could be promoted into `tools/` as standalone
   gates, mirroring P11-A3's pattern (`scan-truncated.mjs` →
   `tools/check_narrative_truncated_endings.mjs`).

6. **Tightening the `흐름이` over-cluster detector.** P12-A5 caught the
   top 2 cluster strings (36 fixture impacts). The remaining 13
   strings each impact 1-5 fixtures. A cluster-aware audit could
   surface them all and let authors decide on rewording.
