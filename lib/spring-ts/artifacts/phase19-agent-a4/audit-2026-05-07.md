# Phase 19 Agent A4 — brief.hook coverage CI gate

Date: 2026-05-07
Owner: P19-A4
Scope: ratchet the 0-dormant-slot state proven in P18-A2 into a CI gate so
future regressions cannot silently re-introduce dormant brief.hook slots.
Owned: `tools/check_hook_coverage.mjs`, `package.json` (scripts only),
`artifacts/phase19-agent-a4/`.

## Headline

Standalone CI gate `ci:hook-coverage` lands. At HEAD `dba1848` (origin/main)
it returns **0 dormant fragmentId slots** with `--max-violations=0`,
matching P18-A2's post-regen baseline (34 authored / 34 emitted / 0 dormant).
The gate fails (exit 1) the moment any authored brief.hook fragment's
`fragmentId` stops appearing in `cell.selectedFragments.brief.fragmentId`
across the 32 `*-tiered.json` sample fixtures.

## What the gate measures

`tools/check_hook_coverage.mjs` walks two trees and computes a set
difference:

1. **Authored slots** — `data/narrative/<cat>/<period>/brief.fragments.json`
   for `<cat> ∈ {overall, career, wealth, health, health_stress, romance,
   family, academic, study_document, expression_children, movement}` and
   `<period> ∈ {today, thisWeek, thisMonth, thisYear, life}`. Every fragment
   whose `hook` field is a non-empty string is counted.
2. **Emit cells** — `artifacts/sample-outputs-2026-05-05-phase3/*-tiered.json`,
   visiting `tieredMatrix.periods[periodKey].overall` and every
   `tieredMatrix.periods[periodKey].byCategory[catKey]`. For cells where
   `cell.brief.hook` is set, harvest `cell.selectedFragments.brief.fragmentId`.

A "dormant" slot is an authored fragment whose `fragmentId` does not appear
in the emit set. This mirrors P18-A2's per-fragmentId dormancy view, which
is the gating signal because authoring intent attaches to fragmentId (two
authored fragments can share hook text legitimately, so per-text dormancy
is reported only as a diagnostic).

The samples directory acts as a read-only oracle. The gate does NOT
regenerate samples — pair it with `ci:samples-stale` (which runs the
generator under a snapshot/restore guard) so a stale-samples drift cannot
mask dormancy.

> **Note on the task brief's `<ageband>` axis** — the live tiered matrix
> structure is `period.byCategory.<cat>.brief.hook`; there is no
> `byAgeBand` level in any sample fixture (verified by walking all 32
> `*-tiered.json` files at HEAD). `ageBand` is an *authoring* axis carried
> in `fragment.gating.ageBand`, surfaced in the gate's dormant-entry
> output for diagnostic locality.

## Gate enforcement

`package.json`:

```json
"ci:hook-coverage": "node tools/check_hook_coverage.mjs --max-violations=0"
```

The flag is explicit (matches the `ci:narrative-*` family pattern), so a
future P-N agent can follow the same ratchet idiom. There is no
`ci:all` aggregator in this `package.json` — `ci:hook-coverage` runs
standalone, alongside `ci:samples-stale`, `ci:narrative-truncated-endings`,
and other per-defect gates.

The gate prints:
- summary line (counts above);
- per-dormant-slot detail when `dormancy.byFragmentSlot.count > 0`
  (fragmentId, cat, period, gating, hook string), capped at
  `--max-samples=N` (default 50);
- a "lowest emit-count tail" — the 5 fragments with the smallest emit
  count across the matrix. This is the fragility forecast: those slots
  are first to fall on a regression.

Exit semantics:
- `dormantCount ≤ --max-violations` → exit 0;
- `dormantCount > --max-violations` → exit 1 + stderr explanation.

A self-test against an empty samples directory confirms the failure path:
`node tools/check_hook_coverage.mjs --samples-dir=/tmp/empty` correctly
prints all 34 authored slots as dormant and returns exit 1.

## Future-drift forecast — first to break

If a regression silently re-introduces dormant slots, these are the
candidates ordered by current emit-count fragility:

| Rank | fragmentId                                  | emit count | Why fragile                                          |
|------|---------------------------------------------|------------|------------------------------------------------------|
| 1    | `wealth.thisYear.brief.balanced.neutral.004`| 2          | BALANCED-only gating; only 2 fixtures match BALANCED |
| 2    | `family.today.brief.young.003`              | 4          | `ageBand:["10-19","20-29"]` narrow audience          |
| 3    | `health.today.brief.strong.elder.001`       | 4          | STRONG × elder ageBand intersection                  |
| 4    | `romance.thisYear.brief.midlife.001`        | 4          | midlife ageBand only                                 |
| 5    | `study_document.today.brief.adult.005`      | 4          | adult ageBand only                                   |

Likely break vectors:
- **Sample-fixture matrix shrinks or its age/strength distribution shifts**
  — if a future commit retires fixtures or rebalances them away from
  BALANCED / midlife / elder coverage, the rank-1 BALANCED fragment is
  the canary.
- **Gating-rule tightens** — any P-N change that adds a `yongshinAlignment`
  or `dayMasterStrength` intersection on top of an already-narrow
  fragment's gating without authoring a sibling fragment could push a
  rank-2..5 fragment to 0 emits (e.g. tightening
  `family.today.brief.young.003` from `young` to
  `young + STRONG-only` would dormant it for the WEAK
  fixtures in the young ageband).
- **Post-processor changes** — if the GyeolSub substitutions in
  `template-engine.ts` change in a way that mutates a fragment's hook
  text into a string the gate's per-text view doesn't reach, the
  per-fragmentId view (the gating signal) still fires, so the gate
  catches it. The per-text diagnostic count in the report would also
  surface the discrepancy.
- **Samples-staleness** — if the samples directory is committed without
  re-running the generator after a saju-ts/dist rebuild (the failure
  mode P18-A2 caught), `ci:samples-stale` should fire first. If
  somehow the staleness gate is bypassed and dormant slots emerge,
  this gate fails second — defense in depth.
