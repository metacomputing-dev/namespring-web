## Authoring pitfall (and the fix that closes ci:hook-coverage)

Initial pass authored siblings at the same specificity as parent (just
`ageBand`). With 4 cohort-matching fixtures distributed across 3
hash-tied candidates, the FNV-1a hash mod-3 of the actual selection
seeds came out `{1, 2, 2, 1}` for the family.young child fixtures —
leaving idx 0 (parent `young.003`) at 0 emits. The same partition issue
applied to romance and study_document. Three new dormant fragmentSlots
would have failed `ci:hook-coverage --max-violations=0`.

The fix: each new sibling carries 2D or 3D gating (e.g., `ageBand` ∧
`birthSeason`, or `ageBand` ∧ `birthSeason` ∧ `gender`). At relax level
0, the new sibling's specificityScore is 2 or 3, beating the parent's
specificityScore of 1 by deterministic dominance. Parent retains the
cohort cells whose attributes do *not* match any sibling's sub-niche.

Per `src/report/tiered/fragment-selector.ts` `specificityScore`:

```
function specificityScore(frag, relaxBefore) {
  let score = 0;
  for (let i = relaxBefore; i < FALLBACK_DIMENSIONS.length; i += 1) {
    const allow = (frag.gating)[FALLBACK_DIMENSIONS[i]];
    if (allow && allow.length > 0) score += 1;
  }
  return score;
}
```

Each non-empty gating dim adds 1. So `{ageBand:[0-9], birthSeason:[spring]}`
scores 2, while `{ageBand:[0-9]}` scores 1. The 2-vs-1 dominance is
deterministic; no hash tiebreak between parent and sibling.
