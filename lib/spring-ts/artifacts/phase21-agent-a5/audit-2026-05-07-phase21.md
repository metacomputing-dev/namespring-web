### I2. `audit-phase12.mjs` `depth_inversion` detector refresh

P14-A5 / P15-A5 / P16-A5 / P17-A5 / P18-A5 / P19-A5 / P20-A5 all
carried this as a recommendation. P21-A2 ships it.

Pre-refresh detector (committed at main `544992b`):

```js
// length-only comparison
if (briefH.plainText.length > standardP0.plainText.length) {
  hits.push({ ... });
}
```

This produced false positives on character-count differences of 1-8
chars where the brief and standard tiers carry genuinely different
prose. Both surfaces are tightly bounded (brief 28-40 chars, standard
first-sentence 30-45 chars), so length deltas are noise.

P21-A2's refresh measures Levenshtein similarity between
particle-stripped, whitespace-normalized forms of the brief headline
and the first sentence of the standard tier:

```js
const a = normalizeForOverlap(briefH.plainText);
const b = normalizeForOverlap(standardP0.plainText);
const dist = levenshtein(a, b);
const similarity = 1 - dist / Math.max(a.length, b.length);
if (similarity >= 0.75) hits.push({...});
```

The 0.75 threshold matches P5's depthCoherence semantic. At main
HEAD the committed `phase12-audit-issues.json` shows
`depth_inversion: 0` even with the old detector — so the refresh is
not closing existing hits, it's preventing future false positives
(detector hardening, not defect fix).

P21-A2's branch is `bc8117a`, scope is
`artifacts/phase12-agent-a5/audit-phase12.mjs` mutation only (no data,
no src, no package.json).

### I3. `ci:hook-concentration` upper-bound gate

P20-A5 §Recommendation #5 noted a sudden jump in `maxHookOnSingleFixture`
above 20 with the same authored corpus would indicate a gating-merge
with too-broad reach. P21-A3 ships the gate.

New script `tools/check_hook_concentration.mjs` reads the
sample-outputs and counts distinct brief.hook strings per fixture.
Threshold `--max-hooks=20`. At main `544992b` the max is 15
(`13-oh-extreme-weak-continuous-tiered`), so 5-hook headroom remains
for normal authoring churn.

The new gate is COMPLEMENTARY to `ci:hook-coverage` (P19-A4) — coverage
detects DORMANT fragmentId slots (under-merge), concentration detects
OVER-MERGE (too many hooks landing on a single fixture). Both gates
together bound the per-fixture hook surface.

`tools/acceptance-manifest.json` declares `ci:hook-concentration` in
`accepted[]`; `ci:acceptance-completeness` accepts the new entry on
A3 merge.
