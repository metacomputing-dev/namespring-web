## Issues fixed this phase

### A. `_coverage/` post-processor `결로 -> 리듬로` cluster grammar leak (10 token edits, 7 files)

`tools/check_orphan_tag_text.mjs` and the other production gates
do not check Korean particle grammar. This was found by the P12-A5
prose corpus scan extended to look for ungrammatical alternative
substitutions emitted by `template-engine.ts:reduceOverusedGyeol`.

#### Detector contract

The post-processor `reduceOverusedGyeol` (see §C1 for src reference,
out of scope) substitutes `결X` -> `흐름X` to reduce repeated `결`
within a paragraph, but if `appliedFlow > 2` it picks an alternative
('리듬', '자리', '호흡', '걸음') and concatenates it with the
original suffix. This produces ungrammatical Korean when the
original suffix was for `결` (which has 종성 ㄹ; particles like
`로` work after ㄹ-final but require `으로` after ㅁ-final like 리듬).

| Pattern | Output | Note |
|---------|--------|------|
| `결로 -> 리듬로` | `리듬로` | wrong: should be `리듬으로` |
| `결을 -> 자리을` | `자리을` | wrong: should be `자리를` (vowel-final) |
| `결로 -> 호흡로` | unattested | would also be wrong |

The data-side fix breaks the source `결` cluster so the
post-processor never reaches the alt-pick branch.

#### Source pattern that triggered the leak

```
의 결이 함께 또렷해지는 시기엔 자격·계약·발표 결이 한 결로 마무리되는 자리가 보여요.
```

Three `결` chars in one text token. After per-token normalize:
- `결이` (1st): appliedFlow=1 -> `흐름이`
- `결이` (2nd): appliedFlow=2 -> `흐름이`
- `결로`: appliedFlow=3 -> alt branch -> `리듬로` (ungrammatical)

Surface impact (before fix): 78 cells across 3 study_document
expert fragments × 26 fixture/period selections produced
`자격·계약·발표 흐름이 한 리듬로 마무리`.

#### Fix shape

Replace `한 결로` with `한 방향으로` in all 10 instances:

```diff
       "templateTokens": [
         ...
         {
           "kind": "text",
-          "value": "의 결이 함께 또렷해지는 시기엔 자격·계약·발표 결이 한 결로 마무리되는 자리가 보여요."
+          "value": "의 결이 함께 또렷해지는 시기엔 자격·계약·발표 결이 한 방향으로 마무리되는 자리가 보여요."
         }
       ]
```

After fix: source has 2 `결` chars. Per-token normalize substitutes
both within the budget — output renders `흐름이 / 흐름이 / 한
방향으로 마무리되는 자리가 보여요`. Clean.

#### Why prior phases didn't catch this

P12-A5 / P13-A5 prose-quality detectors did not include a Korean
particle-grammar check. Identifying ungrammatical post-processor
alternatives requires either (a) authoring an alt-grammar gate in
`tools/`, or (b) reading the post-processor source and reasoning
about which suffixes break under which alternatives. P14-A5's
finding came from the latter (corpus pattern hunt for `리듬로`,
`자리을`, etc., on the regenerated samples). See Phase 15
recommendation #1 for productionizing this.

## Issues observed this phase (deferred / informational)

### C1. `template-engine.ts` per-token normalize loses paragraph-level count (root cause of B3 + A)

`renderFragmentParagraphs` (`src/report/tiered/template-engine.ts:1027`)
calls `normalizeRenderedText(token.value)` per text token (line
1040). The post-processor `reduceOverusedGyeol` (line 699) splits
its input by `\n\n+` and counts `흐름` per paragraph — but its
input is one TEXT TOKEN, not the joined paragraph. As a result:

- A single text token with N `결` cluster gets paragraph-aware
  budgeting (works, see §A fix).
- Multiple text tokens in the same paragraph (separated by
  `{kind:'tag'}` tokens) each get an INDEPENDENT count budget,
  exceeding the global paragraph budget.

This is the architectural cause of both:
- §A: `결로 -> 리듬로` ungrammatical alt within ONE token
  exceeding the budget.
- §B3: 3+ `흐름이` cluster spanning MULTIPLE tokens that
  individually do not exceed the budget.

A src-side fix would replace the per-token normalize with a
per-paragraph normalize: build the paragraph's plain text first
(via `plainTextFromTokens` minus tag insertion), measure
paragraph-level `흐름` count, then apply substitutions to each
token with a SHARED budget counter. Out of P14-A5 scope
(`src/` is forbidden). See §D #1 / #4.

### C2. `depth_inversion` curated detector is now stale post P13-A4

The `audit-phase12.mjs` curated detector compares
`brief.headline.plainText.length` against
`standard.paragraphs[0].plainText.length`. After P13-A4 split
standard tier into 2-5 paragraphs, the first paragraph alone
became shorter than the brief headline in 129 cells. The total
standard prose still substantially exceeds brief, but the metric
the detector uses no longer represents tier inversion.

Recommend updating the detector to compare full standard prose
length (sum of paragraph plainText lengths) against brief, or
deprecating it now that the production tier-shape tests
(`test:tiered-shape`) cover this contract. See §D #5.

### C3. `자리을` ungrammatical alt — out of `_coverage/` scope

Same root cause as §A. 5 cells render `자리을` (wrong, should be
`자리를` for vowel-final stem). Source: `wealth/{life,today,thisWeek,
thisMonth,thisYear}/standard.fragments.json` template `짧은 결과보다
긴 결을` and `큰 결을 한 번에`. Out of `_coverage/` scope. Phase 15
recommendation: extend §A's fix shape to these source files.

### C4. `ci:release-checklist` is interactive (carry-over from P13-A5 §C5)

Requires `--body <path>` or `GITHUB_EVENT_PATH`; cannot run from
worktree-local `npm run`. Exercised at PR creation by GitHub
Actions only. Documented exception, not a defect.

### C5. Hooks usage = 1.11% of cells (mature, but distribution-bottlenecked, P13-A1 follow-on)

The `BriefFortuneText.hook` schema is now wired and emits when
the selected brief fragment carries one. P13-A1 authored 10
hooks; only 2 surface. See §B1 for diagnosis. Phase 15 author
strategy: place hooks on **gated** fragments (e.g., per-ageBand,
per-yongshinAlignment) rather than wildcard floors, OR add
hooks to every brief fragment in the categories that prioritize
them.

## Recommendations for next phase

### High priority

1. **Phase 15 — `tools/check_post_processor_grammar.mjs` gate.**
   Productionize a Korean particle-grammar audit against the
   expanded prose corpus. Patterns to flag:
   - `리듬로`, `호흡로`, `걸음로` (should be `으로`)
   - `자리을`, `걸음을` if stem doesn't end in 종성 (`자리`
     ends in vowel ㅣ -> needs `를`)
   - Future: `리듬마다`, `자리마다`, etc. — any post-processor
     alt + `결` suffix where Korean phonetics break.
   This would have caught both §A (78 leaks) and §C3 (5 leaks)
   automatically and is the cleanest answer to the per-token
   normalize architectural flaw described in §C1.

2. **Phase 15 — Decide `template-engine.ts` per-paragraph normalize
   refactor.** The architectural fix (§C1) replaces per-token
   `normalizeRenderedText(token.value)` with per-paragraph
   `normalizePostJoin(joinedParagraphText)`. This requires care
   because tags get re-inserted as `#label`, but is the right
   long-term shape. P14-A5's data fix (§A) is a workaround;
   the refactor removes the entire defect class. Estimated
   src-touch surface: ~30 LOC in `renderFragmentParagraphs`.

3. **Phase 15 — Author or remove the 8 unused hooks (§B1 / C5).**
   Either:
   a. Move the 6 wildcard-gated hooks to per-ageBand siblings so
      they can fire on real fixtures.
   b. Audit each authored hook and drop the ones whose semantics
      don't translate well to the firing audience.
   c. Add hooks to existing gated fragments to broaden surface.

### Medium priority

4. **Phase 15 — Extend §A fix to categorical fragments.** 12
   `리듬로` and 5 `자리을` leaks remain in `academic/`, `family/`,
   `overall/`, `wealth/` (out of `_coverage/` scope this phase).
   Apply the same `한 결로 -> 한 방향으로` / `긴 결을 -> 긴 그림을`
   fix shape with appropriate per-context wording.

5. **Phase 15 — Refresh or deprecate `audit-phase12.mjs`'s
   `depth_inversion` detector.** Either compare full standard
   prose length (sum across paragraphs) against brief, or
   delete it now that `test:tiered-shape` covers the contract
   (§C2).

### Low priority / informational

6. **Phase 15 — Expand `흐름이` cluster detection.** The 51
   cells from one `overall/` source pattern (§B3) need either
   a data-side rewording (move out of `_coverage/` constraint)
   or a src-side per-paragraph budget refactor (#2). A cluster-
   aware audit could surface authoring decisions.

7. **Phase 15 — brief.hook coverage gate (optional).** A
   `tools/check_brief_hook_coverage.mjs` could measure
   distinct-hooks-emitted vs. authored and warn if the ratio
   stays below e.g. 50%. Low priority because hooks are an
   optional surface; carry-over from P12-A5 §C1 / P13-A5 §C1.
