`git show --name-only 709a96b…` lists ONLY
`lib/spring-ts/tools/regen_samples.mjs`. Verified:

- `grep -E "samples:regen|samples:check" lib/spring-ts/package.json`:
  no matches. The two scripts are absent.
- `ls .github/workflows/`: only `deploy-pages.yml` exists. The new
  workflow file was never added to the repository.

**The script itself works correctly.** P17-A2 used it for the catch-up
regen this phase: `node tools/regen_samples.mjs` ran clean (after
ensuring `lib/saju-ts/node_modules/` was installed, which is itself
a hidden dependency of the helper because saju-ts's `tsc` needs to
exist). The script's `git diff --stat` summary and recommended
commit-message body matched expectations.

**Caveat for the missing GitHub workflow:** any CI runner picking up
the not-yet-shipped `spring-ts-samples-stale.yml` will need to
`npm --prefix lib/saju-ts ci` (or equivalent) before the helper can
build saju-ts/dist. The `ci:samples-stale` script's `npm --prefix
../saju-ts run build && …` pipeline encodes the build step but
**not** the install step. P17-A2 hit this empirically (the helper
errored with `'tsc' is not recognized` on first invocation; the
workaround was to `cd lib/saju-ts && npm install`). The Phase 17+
re-ship of the workflow file should include both `npm ci` for
`lib/spring-ts` and `npm ci` for `lib/saju-ts` as setup steps, in
the order spring-ts → saju-ts (or both in parallel since they
don't depend on each other in install order).

**Recommendation (Phase 17+ #1, high priority):** re-ship the missing
two deliverables. They were almost certainly drafted but lost during
the same rate-limit episode that swallowed P16-A5's audit doc. The
gain is exactly the process improvement P16-A4 was designed to
deliver: any data-modifying agent (A2/A3/A4) can run
`npm run samples:regen` instead of remembering the longer command,
and the GitHub workflow catches stale samples on every PR.

git diffs always show it changing across worktrees, generating

`generate-samples.ts` write a worktree-relative path

path. This eliminates the entire diff-noise class.

The `ci:samples-stale` gate has now caught **three consecutive
phases** of stale samples:

| Catch-up phase | Stale samples at session start | Root cause                                                                              |
|----------------|--------------------------------|-----------------------------------------------------------------------------------------|
| P14-A5         | 33 / 37                        | P13-A4 paragraph splits regen happened in different worktree                            |
| P15-A5         | 34 / 37                        | P14-A5 regen used pre-P14-A2 dist, P14-A2 paragraph appends not surfaced                |
| P17-A2         | 34 / 37                        | P16-A3 regen used pre-P16-A2 source state, P16-A2 grammar fixes reverted in render      |

The gate is fundamentally working as designed — it catches the
drift on every iteration. But the recurrence reveals that the
process improvement from P16-A4 (the regen helper script) **did
not actually reach the agents who needed it**, because:

1. The workflow file (deliverable #3) was never shipped, so PR
   reviewers don't see a CI failure that would force them to run
   `samples:regen`.
2. The `samples:regen` package.json script (deliverable #2) was
   never shipped, so the helper is invokable only by `node tools/...`,
   which agents may not know about.
3. The audit doc that would explain the helper (P16-A5) was never
   produced.

P17-A2 closes the audit gap; #1 and #2 still need closure (Phase 17+
recommendation #1).

### D2. `template-engine.ts` per-token normalize loses paragraph-level count (still-deferred carry-over from P14-A5 §C1)

`renderFragmentParagraphs` (`src/report/tiered/template-engine.ts:1027`)
calls `normalizeRenderedText(token.value)` per text token. The
post-processor `reduceOverusedGyeol` splits its input by `\n\n+`
and counts `흐름` / `결` per paragraph — but its input is one TEXT
TOKEN, not the joined paragraph. P15-A2 batchim-aware alt
substitution fixed the immediate consequence (no more ungrammatical
particles); P15-A2's per-paragraph normalize wrapper plus P15-A4's
source rewording resolved the visible cluster. But the **architectural
issue** remains: per-token normalization cannot count tokens that
span tag boundaries.

**Out of P17-A2 scope** (`src/` is forbidden). Phase 17+ would still
benefit from the cleaner refactor (carry-over from P14-A5 #2 and
P15-A5 #2), though its priority is now lower because the visible
defect classes have been zeroed.

### D3. brief.hook coverage gap closed; remaining authoring decisions (carry-over from P15-A5 §C2)

P15-A5 §C2 / P14-A5 §C5 flagged that 8 of 10 authored hooks were
dormant under wildcard gating. P15-A3 strengthened gating on the
existing 2 firing hooks (no new hooks). P16-A3 took the alternative
authoring path: **add 10 new hooks on already-gated fragments**
(weak_neutral / strong / age_band) so they fire deterministically.
This worked: all 10 P16-A3 hooks now fire, and the legacy P13-A1
wealth.thisYear hooks gained 13 additional fixture wins via the
expanded spec-2 path coverage.

The remaining 6 of 32 fixtures without any hook (18.75%) are
fixtures whose every `(category, period)` cell happens to choose a
non-hook-bearing fragment under their specific
`(dayMasterStrength, yongshinAlignment, ageBand, gender, season)`.
Phase 17+ #4 would either:
- author hooks on per-fixture-targetable fragments to push coverage
  toward 100%, or
- accept 81.25% as the production ceiling because hooks are
  optional / additive.

### D4. `ci:release-checklist` is interactive (carry-over from P13-A5 §C5)

Documented exempt; not a defect.

## Recommendations for Phase 17+

### High priority

1. **Phase 17+ — Re-ship P16-A4's missing deliverables.** Add to
   `lib/spring-ts/package.json`:
   ```
   "samples:regen": "node tools/regen_samples.mjs",
   "samples:check": "npm run ci:samples-stale"
   ```
   Add `.github/workflows/spring-ts-samples-stale.yml` with
   path-filtered triggers on `lib/spring-ts/data/narrative/**`,
   `lib/spring-ts/src/**`, `lib/spring-ts/artifacts/sample-outputs-2026-05-05-phase3/**`,
   and `lib/saju-ts/src/**`. This closes the regen-race process
   gap definitively. The workflow YAML is the single piece that
   would move the catch class from "audit-phase recurring" to
   "PR-time blocking."

2. **Phase 17+ — Close hook adoption gap toward 100% (optional ceiling).**
   Author hooks on fragments that lose to current spec winners for
   the remaining 6 of 32 fixtures (18.75%). Carry-over from D3.
   Targets identified by the inverse of P16-A3's
   `find-winners.mjs` output.

3. **Phase 17+ — Decide on `template-engine.ts` per-paragraph
   normalize refactor.** Carry-over from P14-A5 #2 / P15-A5 #2.
   Priority now lower (the visible defect classes are zeroed)
   but the architectural debt remains. The cleaner refactor would
   make the post-processor robust against future fragment authoring
   that introduces multi-token paragraphs with `결` / `흐름`
   sequencing.

### Medium priority

4. **Phase 17+ — Refresh or deprecate `audit-phase12.mjs`'s
   `depth_inversion` detector.** Carry-over from P14-A5 #5 / P15-A5
   #5. Either compare full standard prose length (sum across
   paragraphs) against brief, or delete now that `test:tiered-shape`
   covers the contract.

5. **Phase 17+ — Make `outputDirectory` worktree-relative.** Carry-
   over from this phase §C4. Edit `generate-samples.ts` to write
   `path.relative(process.cwd(), outDir)` instead of `path.resolve()`.
   Eliminates index.json diff noise across worktrees.

### Low priority / informational

6. **Phase 17+ — Hook coverage gate (optional).** Carry-over from
   P14-A5 #7 / P15-A5 #8. A `tools/check_brief_hook_coverage.mjs`
   could measure distinct-hooks-emitted vs. authored and warn if
   the ratio drops below e.g. 50%. Lower priority post P16-A3 since
   the ratio is now 100% (all 15 distinct hook strings authored
   are firing).

7. **Phase 17+ — Audit `min15-*-floor` 84 wildcard-floor cells.**
   Carry-over from P15-A5 §C1. These are 2-paragraph cells where
   `min15-*-floor` wildcard wins over more-specific gating.
   Determining whether a 3rd paragraph is appropriate at the
   wildcard level requires per-fixture review of which fragments
   are losing to the floor.
