## Failure mode this prevents

The complementary gate to `ci:hook-coverage`. Where `ci:hook-coverage`
catches **dormant** authored hooks (one-sided lower bound: every
authored fragmentId must fire **somewhere**), `ci:hook-concentration`
catches **over-merged** hooks (one-sided upper bound: no single fixture
should saturate above the safety threshold). Together they bound the
emit distribution from both ends.

Specific regressions this catches:

1. A gating predicate broadened too far in
   `data/narrative/<cat>/<period>/brief.fragments.json`, letting one
   fragmentId fire across category × period cells of a single fixture.
2. A post-processor edit (e.g., `template-engine.ts` GyeolSub) that
   collapses what used to be diverse hook strings into a single
   shared text — invisible to `ci:hook-coverage` if the underlying
   fragmentId is still selected, but visible here as a concentration
   spike in the post-substituted output.
3. A fragment-selector tweak (`tiered/fragment-selector.ts`) that
   drops cohort filtering and lets the same hook surface across cells
   it should not.

## Methodology

Mirrors `tools/check_hook_coverage.mjs` for ergonomic and operational
parity (same flag idioms, same samples-dir resolution, same
`-tiered.json$` glob, same `tieredMatrix.periods[*].(overall |
byCategory[*])` walk). Differs in:

- Per-fixture aggregation (the per-fixture Set is the unit of
  measurement, not the global fragmentId set).
- Distribution stats over fixtures (min/median/max/mode/mean).
- One-sided upper-bound gate (`distinctHooks > maxHooks`); a fixture
  with 0 hooks is not a violation, because coverage is owned by the
  sibling gate.

## Carry-overs and recommendations

1. **Re-tune threshold if/when authored corpus grows.** Current
   `--max-hooks=20` is anchored to the P18/P19/P20 stable max=15. A
   future plan-driven authoring expansion that legitimately raises
   the natural ceiling should update both the threshold and this
   audit's "P20-A5 max=15" anchor.

2. **Pair with `ci:samples-stale`.** Same as `ci:hook-coverage`: the
   samples directory is read-only here. If the saju-ts engine
   regresses, samples must be regenerated for the gate to surface
   the new distribution.

3. **Optional: per-period concentration view.** The current gate
   collapses across all 5 periods × 11 categories. A per-period view
   could catch cohort-specific over-merge (e.g., `life` saturating
   while `today` stays sparse). Out of scope for this phase; tracked
   for P22+ if the basic gate trips.
