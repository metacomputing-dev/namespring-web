## Issues fixed this phase

### A. Sample regen catch-up (the inherited drift)

`artifacts/sample-outputs-2026-05-05-phase3/{01..35}-*.json` plus
`index.json` were stale by 34/37 files at session start. Cause: at
P14-A5's regen commit `c49ceae` (timestamp 21:17:41), four prior
P14-A2 commits (`b2c4318`, `ff5624b`, `7e6f060`, `827efbc`,
all between 21:08-21:11) had already landed paragraph appends to
`_coverage/min15-*-floor.fragments.json` and the `season-context` /
`currentseason` files — but the c49ceae regen produced output that
matches a state WITHOUT those appends.

The session-start `ci:samples-stale --json` output shows divergence
patterns consistent with paragraph-shape changes: every divergence
adds a new `{ "tokens": [{...text...}], "plainText": "..." }` entry
to `standard.paragraphs[]`, with the new content matching exactly
the 3rd-paragraph values P14-A2 added.

#### Hypothesis on the missed surface

There are two plausible explanations:

1. **Stale build dependency.** P14-A5's regen ran with a `saju-ts/dist`
   that was built before P14-A2's data lands; `npm --prefix ../saju-ts
   run build` was not part of the regen step in P14-A5. (Only
   `ci:samples-stale` re-builds saju-ts as part of its npm script.)

2. **Worktree race.** P14-A5 (or a parallel agent) ran the regen
   from a worktree branched off an earlier commit before P14-A2
   landed on `main` / `worktree-*-a327b607281f3297f`.

Either way, the production-grade response is the same: re-run the
regen with the now-current data + dist. The `ci:samples-stale` gate
caught this on session start (its second production catch in two
phases — P14-A5 was its first), validating the gate's design
end-to-end.

#### Verification

After running `npx tsx artifacts/sample-outputs-2026-05-05-phase3/
generate-samples.ts` twice (clean → snapshot → run again →
snapshot), only `generatedAt` and `outputDirectory` differ between
the two runs. Byte-stable.

After running `ci:samples-stale` (which re-builds saju-ts +
re-spawns the generator + masks generatedAt/outputDirectory), the
gate reports 0 violations, sampleFiles=37.

## Issues observed this phase (deferred / informational)

### D1. P14-A5's regen-vs-data race is a process gap (meta-observation)

The `ci:samples-stale` gate has now caught two consecutive phases
of stale samples:
- P13-A5 → P14-A5 catch-up: 33 / 37 stale (P14-A5 §B)
- P14-A5 → P15-A5 catch-up: 34 / 37 stale (this phase §A)

In both cases, a downstream agent (P13-A4 standard 3-7 paragraph
splits, then P14-A2 standard ≥3 paragraph appends to coverage
floors) modified `data/narrative/` AFTER an upstream regen, and the
A5 audit phase had to run the regen catch-up.

The gate is fundamentally working as designed — it caught the drift
in both cases. But the situation reveals a process inefficiency:
the regen step is being treated as part of the audit phase rather
than part of the data-modifying phase.

**Recommendation (Phase 16 #7, low priority):** wire `ci:samples-stale`
into a pre-commit hook or pre-merge agent acceptance gate so that
data-modifying phases (A2 / A3 / A4) regenerate samples in the same
session. The existing CI gate would still catch any miss, but the
A5 audit phase would no longer need to absorb regen catch-up as
~3-4K line-equivalent of mechanical work.

### D2. `template-engine.ts` per-token normalize loses paragraph-level count (carry-over from P14-A5 §C1)

`renderFragmentParagraphs` (`src/report/tiered/template-engine.ts:1027`)
calls `normalizeRenderedText(token.value)` per text token. The
post-processor `reduceOverusedGyeol` splits its input by `\n\n+`
and counts `흐름` per paragraph — but its input is one TEXT TOKEN,
not the joined paragraph. As a result:
- Single text token with N `결`: paragraph-aware budgeting works.
- Multiple text tokens in same paragraph (separated by `{kind:'tag'}`
  tokens): each gets independent count budget, exceeding global
  paragraph budget.

This is the architectural cause of both:
- P14-A5 §A: `결로 -> 리듬로` ungrammatical alt within one token
  exceeding budget. (P14-A5 fixed all `_coverage/` instances by
  rewriting source; 17 instances remain in non-coverage scope.)
- P14-A5 §B3: 3+ `흐름이` cluster across multiple tokens.

Out of P15-A5 scope (`src/` is forbidden). Phase 16 #2 is the
src-side fix.

### D3. `depth_inversion` curated detector is now stale post P13-A4 (carry-over from P14-A5 §C2)

The `audit-phase12.mjs` curated detector compares
`brief.headline.plainText.length` against
`standard.paragraphs[0].plainText.length`. Post P13-A4 + P14-A2
standard tier averages 3 paragraphs; comparing only paragraph[0]
to brief headline produces 129 false positives. Total standard
prose still substantially exceeds brief.

Phase 16 #5: update detector to compare full standard prose length
(sum across paragraphs) against brief, or deprecate it now that
`test:tiered-shape` covers the contract.

### D4. `자리을` ungrammatical alt — out of `_coverage/` scope (carry-over from P14-A5 §C3)

5 cells render `자리을` (wrong, should be `자리를` for vowel-final
