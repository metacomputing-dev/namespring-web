# Phase 11 Agent A5 — Cross-Fixture Audit + Minor Fix

Date: 2026-05-06
Owner: P11-A5
Scope: cross-fixture consistency audit over 32 tiered fixtures in
`artifacts/sample-outputs-2026-05-05-phase3/`, plus same-input/different-target-date

## Headline

The 32-fixture corpus is healthy: prose units total 11,099 across 32 fixtures
(346.8 prose units per fixture, 5 periods × 11 categories × 3 depths). Cross-
fixture group cohesion is strong (mean within-group distinct ratio 0.48–0.80
for size-2/3 groups and the 6-fixture jonggyeok set), and same-input/different-
targetDate variation is good (377 cells compared, 76 fully distinct across 3
target dates, mean per-period distinct ratio 0.61–0.68).

This audit also surfaced a **new defect class** not covered by prior phases:
**21 orphan-tag-text occurrences** across 13 fragment files where a glossary
term was rendered as bare prose (`화개의 결과 #문창귀인`) instead of as a tag
token (`#화개의 결과 #문창귀인`). Parallel sibling fragments at the same axis
correctly use the tag form. All 21 occurrences are fixed in this phase.

## Audit methodology

### Tooling

1. `extract-prose.mjs` — walks each tiered fixture's `tieredMatrix` and emits
   `(fixture, period, category, depth, slot, cellKey, plainText)` records.
   `cellKey = period/category/depth/slot` lets us bucket "the same logical
   slot" across fixtures. Output: `prose-corpus.json` (11,099 records, 32
   fixtures), `prose-corpus.tsv`.
2. `audit-cross-fixture.mjs` — computes per-cell distinct ratios, fragment
   reuse heatmap, group cohesion stats, and same-seed cluster divergence.
   Output: `cross-fixture-report.json`.
3. `generate-multi-target-dates.ts` — runs the same Choi Seongsoo input
   across 3 different target dates (2026-05-05, 2026-08-15, 2027-02-04)
   and emits 3 tiered matrices; `audit-multi-targetdate.mjs` cell-by-cell
   diffs them. Output: `multi-target-{date}.json`, `multi-target-report.json`.
4. `find-bare-tag-leadin.mjs`, `find-bare-leadin-broader.mjs`,
   `find-bare-leadin-v3.mjs` — three iterations of a precision-targeted
   detector for orphan glossary terms in text tokens.
5. `scan-tag-consistency.mjs` — verifies each fragment's `tags` array
   exactly matches the set of `tagId` values in its `templateTokens`.
6. `generate-heatmap.mjs` — produces `fragment-reuse-heatmap.tsv` for the
   top-50 most-reused prose strings.

### Acceptance pre-baseline

`test:tiered-determinism` was confirmed 4/4 PASS before any data change.
`selectionSeed equal across calls` and `different targetDate yields different
selectionSeed` are the existing CI guarantees that this audit relies on.

#### How detected

Three iterations of detector tightened the precision:

1. `find-bare-tag-leadin.mjs` — text token ENDING with `<label>의 결과 ` /
   `<label>의 자리` / `<label>의 흐름` / `<label>의 결` followed immediately
   by a tag token. 8 hits.
2. `find-bare-leadin-broader.mjs` — same pattern but across whole rendered
   text per fragment, AND only if the same `(label, stem)` appears tagged
   in any sibling fragment of the same `(category, period, depth)` axis,
   AND the offending fragment doesn't already use the label as a tag (so
   it's not the standard "introduce-with-#-then-rephrase-without" pattern).
   10 additional hits.
3. `find-bare-leadin-v3.mjs` — broader stems (`결이|결과|자리|흐름|신호|기운|균형|평균`).
   3 additional hits.

False-positive control: the third filter (`fragment doesn't already use the
label as a tag elsewhere`) is critical because `#식신…식신의` and `#정재…
정재가` are intentional Korean prose: once a topic is introduced as a
hashtag, repeating it in subsequent description text without `#` is clean
style and not a bug.

#### Why these are bugs

- The `tagId` corresponding to the bare label is **not** in the fragment's
  `tags` array, demonstrating it was never intended as a "stylistic
  re-mention" — the author simply forgot to make it a tag.
- The parallel sibling fragments (other axes / other gating values for the
  same cell coordinate) consistently use the tag form for the same word.
- Visible to user: rendered prose differs by `#` presence, breaking the
  consistent "hashtag tells you this is a glossary term you can tap on" UX
  contract.

### B. Outstanding observations (deferred — out of P11-A5 scope)

#### B1. Expert-depth wildcard floors — heavy by-design reuse (severity: low)

47 of 50 cells with distinct ratio < 0.3 are expert-depth. The wildcard
floor fragments (gating `{}`) emit the same shinsal/궁/용신 prose for
every chart. This is intentional — they exist to guarantee minimum prose
length per cell. Possible directions for a future phase:

1. Author multiple variants per floor and select by `selectionSeed` so the
   floor itself adds per-fixture variation.
2. Demote the floor templates to lower priority so axis-specific fragments
   take precedence more often.
3. Audit whether each floor template earns its keep — some may be
   removable if newer authored fragments cover the same ground.

This is a structural design call, not a bug.

#### B2. Some `today/overall/standard.para0` cells stable across target dates (severity: low)

For Choi Seongsoo's chart, the `today/overall/standard.para0` cell renders
the same prose for May 5 / August 15 / February 4, despite distinct
selectionSeeds. Inspection: these cells are gated by life-stage/yongshin-
alignment, both saju-stable, so the single matching fragment fires the
same way regardless of date. Engine-side behavior is correct; the cell's
authoring intent is "this is a stable interpretation given the user's
constitution," not "what is today's vibe."

If product wants daily-cycle freshness here, the fix is at the data layer
(add date-cycle gated variants) or fragment-selection layer (favor
date-stable fragments lower than date-aware ones). Out of P11-A5 scope.

#### B3. P10-A5 leftover — 14 glossary label inconsistencies (severity: low)

Documented in P10-A5 audit-2026-05-06.md §C1 — 14 distinct `tagId →
canonical-label` mismatches across ~200 fragment-level `tag.label` overrides
(e.g., `안정성지수` glossary vs `안정 지표` / `안정 지수` fragment uses).
P11-A5 did not touch these because they require coordination with
`template-engine.ts` particle normalization. Recommendation: dedicated
Phase 12 PR per P10-A5 §3.

## Recommendations for next phase

### High priority

1. **Phase 12 — `ci:narrative-tag-token-parity` gate.** Add a CI test that
   asserts: for every fragment, every glossary label that appears as a tag
   token elsewhere in the fragment must NOT also appear in any text token
   value at a position not preceded by `#`. With one-time author exception
   list for intentional re-mentions. The detectors authored in this phase
   (`find-bare-tag-leadin.mjs`, `find-bare-leadin-v3.mjs`) provide the
   logic; productionize as a `tools/` script.

### Medium priority

2. **Phase 12 — cross-period selection seed audit on the engine side.**
   Confirm that fragments tagged `gating.today` actually use date-aware
   features (current 일진, current month-pillar overlay, etc.) not just
   life-arc constants.

### Low priority / informational

3. **Phase N — expert-depth floor variation.** As noted in §B1, the
   median expert distinct ratio of 0.107 is by-design but is a structural
   design choice. Worth a dedicated thread on whether to author multiple
   variants per floor.
