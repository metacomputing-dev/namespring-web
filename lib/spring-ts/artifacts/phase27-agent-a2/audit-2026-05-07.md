## Diagnosis

`career.thisWeek.brief.age40plus.009`
(`lib/spring-ts/data/narrative/career/thisWeek/brief.fragments.json`,
line 273). Gating: `ageBand: ["40-54", "55-69", "70+"]`. The fragment
**is** selected — `ci:hook-coverage` reports 0 dormant by fragmentId
slot, and the hook surfaces as `cell.brief.hook` across 7 brief-tier
cells in the 32-fixture matrix (e.g. `12-jeong-extreme-strong-continuous`

line 7209, etc.).

### Why `dormantHookStringsByText` reported 1

This is the documented "post-processor counting artifact" first
characterised by P18-A5 §C2. The chain:

1. Authored source: `"쌓아 온 결이 자리를 받쳐 줘요."`
2. `src/report/tiered/template-engine.ts` GYEOL_SUBS table line 777
   (`/(?<![가-힣])결이/g -> 흐름이`) rewrites `결이 -> 흐름이` at render
   time.
3. Emitted form across all 7 emit cells: `"쌓아 온 흐름이 자리를
   받쳐 줘요."`
4. `artifacts/phase23-agent-a4/measure_p23.mjs` line 405-407:
   `dormantHookTextCount = authoredHookStrings.filter(h =>
   !hookStrings.has(h))` — the comparison is **direct string equality**
   without applying the post-processor. So `"쌓아 온 결이 자리를
   받쳐 줘요."` (source) is reported as dormant even though
   `"쌓아 온 흐름이 자리를 받쳐 줘요."` (emit) is present.
5. `tools/check_hook_coverage.mjs` line 108 + 266 **does** apply
   `applyPostProcessor` before comparing, which is why
   `ci:hook-coverage`'s "dormant by hook text" diagnostic correctly
   showed 0 even at the prior HEAD.

### Classification (per task framing)

This is a third category beyond the task's stated A/B taxonomy. It is
closest to **case A (effective duplicate)**: the source form
`쌓아 온 결이 자리를 받쳐 줘요.` and the emit form `쌓아 온 흐름이
자리를 받쳐 줘요.` are two representations of one logical hook
string — the GYEOL post-processor normalises the former onto the
latter. `measure_p23.mjs`'s without-post-processor view sees them as
two distinct strings, so the source-form is "dormant" (never appears
verbatim in emits). The fix collapses the source onto the emit form.

This is **not** case B (gating dormant): the fragment fires on
multiple fixtures already.

## Fix

**Single 1-line source rewrite** in
`lib/spring-ts/data/narrative/career/thisWeek/brief.fragments.json`
line 292:

```diff
-      "hook": "쌓아 온 결이 자리를 받쳐 줘요.",
+      "hook": "쌓아 온 흐름이 자리를 받쳐 줘요.",
```

### Why this is the right move

- Source form now == emit form. The post-processor becomes a no-op for
  this hook (no `결이 -> 흐름이` substitution needed).
- `measure_p23.mjs`'s without-post-processor view now finds the
  authored string verbatim in `hookStrings` -> dormancy 1 -> 0.
- The rendered emit text across all 7 emit cells is byte-identical to
  the prior state — verified by the diff against
  `artifacts/sample-outputs-2026-05-05-phase3/*.json`: the only
  changes are timestamp updates (`generatedAt` fields) from the
  fresh regen; no hook content delta. So `test:namespring-compat`,
  `ci:narrative-voice`, `ci:hook-concentration` are all undisturbed.
- The new hook is 13 syllables, well under the ≤24 자모 ceiling.
- Uniqueness check: a `grep -rn "쌓아 온 흐름이 자리를" data/` returns
  only the new hook itself — no other authored fragment uses this
  string, so the distinctHookStrings count stays at 48.
